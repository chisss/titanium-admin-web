### 2.5　🔴 一次目视误判的纠正（方法记录）

首轮目视 `06-policy-list` 对时，判定「**保额列 `¥500,000.0` 被截断**」。真机 DOM 实测推翻了该结论：

```
保额 ¥500,000.00  →  scrollWidth 120 = clientWidth 120  →  clipped = false（未截断）
保单号 POL-…      →  scrollWidth 165 > clientWidth 160  →  clipped = true （真截断，5px 溢出）
```

**结论**：截图中「缺个 0」是**表格横向滚动位置**在截图瞬间的呈现 + 图片缩放判读误差，**非 CSS 缺陷**；真正被截断的只有**保单号列**（轻微，5px）。

> **可复用判据（本批次第三次同族教训）**：**像素级的「看起来有问题」必须由 DOM 实测裁定**（`scrollWidth/clientWidth`），目视只能用于**布局结构的对照**。这与 `ui-202` 定型的「计数型结论一律由 DOM 实测得出」同源 —— 前两次作用于**计数**，这次作用于**判读**。

## 五、批次最终结论

**第二轮把「机制性不统一」收敛为「机制已统一，但令牌消费尚未跟上」。**

- **可机械复验的部分已全部达标**：主题派生变量、色值/令牌、错误态契约、表格语言、操作列、断点、演示账号清理 —— 24 条守卫规则全绿，且**无一条放宽 target**。
- **未达标的部分已定量**：字号令牌使用率 **5.6%**、间距 **3.0%**，时间文案 **7 页 8 列**未格式化。
- **最重要的产物不是分数，而是三条可复用判据**：
  1. **计数型规则必须问它数的是不是我交付的那个东西**（S-12 / G-01 / D-02 三次同族）
  2. **像素级的「看起来有问题」必须由 DOM 实测裁定**（`06-policy-list` 截断误判）
  3. **守卫全绿 ≠ 支柱达标**：判据必须覆盖**消费侧**，否则「表建好了没人用」可以一路绿灯
